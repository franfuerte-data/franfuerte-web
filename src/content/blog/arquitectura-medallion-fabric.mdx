## Capa Bronze: Los datos tal como llegan

La capa Bronze es tu **zona de aterrizaje (landing zone)**. Los datos llegan exactamente como los recibes de los sistemas fuente, sin transformaciones de negocio.

<div class="choice-grid">
  <div class="choice-card card-amber">
    <h4>Principios de Bronze</h4>
    <ul>
      <li><strong>Inmutabilidad:</strong> los archivos raw no se modifican nunca</li>
      <li><strong>Particionado por fecha de ingesta</strong> (no por fecha del negocio)</li>
      <li><strong>No inferir tipos:</strong> en Bronze todo es string</li>
      <li><strong>Metadata de trazabilidad:</strong> _ingestion_ts, _source_file, _batch_id</li>
    </ul>
  </div>
  <div class="choice-card card-violet">
    <h4>Lo que NO va en Bronze</h4>
    <ul>
      <li>Conversiones de tipos de negocio</li>
      <li>Validaciones de reglas de negocio</li>
      <li>Deduplicación basada en lógica de negocio</li>
      <li>Joins o enriquecimientos con otras fuentes</li>
    </ul>
  </div>
</div>

```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import current_timestamp, input_file_name, lit
from datetime import datetime

spark = SparkSession.builder.getOrCreate()

BATCH_ID    = datetime.now().strftime("%Y%m%d_%H%M%S")
SOURCE_NAME = "erp_sap_ventas"

# Leer archivos raw — NO inferimos tipos en Bronze
df_raw = spark.read.format("csv") \
    .option("header", "true") \
    .option("inferSchema", "false") \
    .option("encoding", "UTF-8") \
    .load(f"Files/landing/{SOURCE_NAME}/")

# Solo metadata de ingesta, cero transformaciones de negocio
df_bronze = df_raw \
    .withColumn("_ingestion_ts",   current_timestamp()) \
    .withColumn("_source_file",    input_file_name()) \
    .withColumn("_batch_id",       lit(BATCH_ID)) \
    .withColumn("_source_system",  lit(SOURCE_NAME))

# Particionado por año/mes de ingesta para gestión del ciclo de vida
df_bronze.write \
    .format("delta") \
    .mode("append") \
    .partitionBy("_ingestion_year", "_ingestion_month") \
    .saveAsTable("bronze.ventas_raw")

print(f"Bronze OK: {df_bronze.count():,} registros [Batch: {BATCH_ID}]")
```

## Capa Silver: Datos de confianza

La capa Silver es donde ocurre la mayor parte del trabajo de ingeniería. Aquí transformamos datos raw en datos **limpios, tipados y confiables**.

Transformaciones típicas en Silver:
- Conversión de tipos (strings a fechas, enteros, decimales)
- Deduplicación con lógica de ventana
- Validación de reglas de negocio con audit trail de rechazados
- Normalización de valores (mayúsculas, trimming)
- Upsert (merge) para gestionar actualizaciones incrementales

```python
from pyspark.sql.functions import (
    col, to_date, trim, upper, when, lit, current_timestamp,
    row_number
)
from pyspark.sql.window import Window
from pyspark.sql.types import DecimalType, IntegerType
from delta.tables import DeltaTable

spark = SparkSession.builder.getOrCreate()

df_bronze = spark.table("bronze.ventas_raw")

# 1. Tipado y limpieza
df_typed = df_bronze \
    .withColumn("fecha_venta",  to_date(col("fecha_raw"), "dd/MM/yyyy")) \
    .withColumn("importe_neto", col("importe_raw").cast(DecimalType(18, 2))) \
    .withColumn("cantidad",     col("cantidad_raw").cast(IntegerType())) \
    .withColumn("canal",        upper(trim(col("canal_raw"))))

# 2. Audit trail: registros inválidos a tabla de rechazados
df_invalid = df_typed.filter(
    col("fecha_venta").isNull() |
    col("importe_neto").isNull() |
    (col("importe_neto") <= 0)
).withColumn("_reject_reason",
    when(col("fecha_venta").isNull(),   lit("FECHA_INVALIDA"))
    .when(col("importe_neto").isNull(), lit("IMPORTE_NULO"))
    .otherwise(lit("IMPORTE_NO_POSITIVO"))
)

df_invalid.write.format("delta").mode("append") \
    .saveAsTable("silver.ventas_rechazadas")

# 3. Deduplicar — quedarse con el registro más reciente por venta_id
window = Window.partitionBy("venta_id").orderBy(col("_ingestion_ts").desc())
df_valid = df_typed \
    .filter(col("fecha_venta").isNotNull() & (col("importe_neto") > 0)) \
    .withColumn("_rn", row_number().over(window)) \
    .filter(col("_rn") == 1).drop("_rn")

# 4. Upsert incremental con Delta merge
if DeltaTable.isDeltaTable(spark, "Tables/silver/fact_ventas"):
    DeltaTable.forName(spark, "silver.fact_ventas") \
        .alias("t") \
        .merge(df_valid.alias("s"), "t.venta_id = s.venta_id") \
        .whenMatchedUpdateAll() \
        .whenNotMatchedInsertAll() \
        .execute()
else:
    df_valid.write.format("delta").mode("overwrite") \
        .saveAsTable("silver.fact_ventas")

print(f"Silver OK:     {df_valid.count():,} registros")
print(f"Rechazados:    {df_invalid.count():,} en audit trail")
```

## Capa Gold: El modelo de negocio

La capa Gold está diseñada para el **consumo final**: Power BI, APIs de negocio, modelos de ML. Los datos hablan el lenguaje del negocio, no el de los sistemas fuente.

```python
# Modelo dimensional Gold con Spark SQL
spark.sql("""
    CREATE OR REPLACE TABLE gold.dim_fecha AS
    SELECT DISTINCT
        CAST(DATE_FORMAT(fecha_venta, 'yyyyMMdd') AS INT) AS fecha_id,
        fecha_venta,
        YEAR(fecha_venta)                                  AS anio,
        QUARTER(fecha_venta)                               AS trimestre,
        MONTH(fecha_venta)                                 AS mes,
        WEEKOFYEAR(fecha_venta)                            AS semana,
        DAYOFWEEK(fecha_venta)                             AS dia_semana,
        CASE WHEN DAYOFWEEK(fecha_venta) IN (1,7)
             THEN true ELSE false END                      AS es_fin_semana
    FROM silver.fact_ventas
    ORDER BY fecha_id
""")

spark.sql("""
    CREATE OR REPLACE TABLE gold.fact_ventas_kpi AS
    SELECT
        CAST(DATE_FORMAT(v.fecha_venta, 'yyyyMMdd') AS INT) AS fecha_id,
        v.canal,
        v.cliente_id,
        v.producto_id,
        SUM(v.cantidad)                 AS unidades_vendidas,
        SUM(v.importe_neto)             AS ingresos_netos,
        SUM(v.importe_neto * 0.21)      AS iva_total,
        SUM(v.importe_neto * 1.21)      AS ingresos_brutos,
        COUNT(DISTINCT v.venta_id)      AS num_transacciones,
        AVG(v.importe_neto)             AS ticket_medio
    FROM silver.fact_ventas v
    WHERE v.fecha_venta >= '2024-01-01'
    GROUP BY
        CAST(DATE_FORMAT(v.fecha_venta, 'yyyyMMdd') AS INT),
        v.canal, v.cliente_id, v.producto_id
""")

print("Gold OK: Modelo dimensional actualizado")
```

## Mejores prácticas que marcan la diferencia

### Nomenclatura consistente entre capas

```
lh_bronze_{dominio}   → lh_bronze_ventas, lh_bronze_rrhh
lh_silver_{dominio}   → lh_silver_ventas
lh_gold_{dominio}     → lh_gold_analytics
nb_{capa}_{acción}    → nb_silver_transform_ventas
df_{fuente}_{acción}  → df_erp_ingest_ventas
```

### Observabilidad desde el primer día

```python
import json
from datetime import datetime

def log_step(layer: str, table: str, records: int,
             status: str, error: str = None) -> None:
    """Log estructurado para el pipeline de Medallion."""
    entry = {
        "timestamp": datetime.utcnow().isoformat(),
        "layer":     layer,
        "table":     table,
        "records":   records,
        "status":    status,   # "success" | "warning" | "error"
        "error":     error
    }
    # En producción: enviar a tabla de audit en Fabric o Log Analytics
    print(json.dumps(entry))

# Uso
log_step("silver", "fact_ventas", 150_000, "success")
log_step("silver", "ventas_rechazadas", 42, "warning",
         "42 registros con fecha invalida")
```

### Validaciones de calidad antes de escribir en cada capa

```python
def validate_silver(df) -> None:
    """Validaciones críticas de Silver — lanza excepción si falla."""
    
    total = df.count()
    checks = [
        ("sin_venta_id_nulo",  df.filter(col("venta_id").isNull()).count() == 0),
        ("sin_importes_neg",   df.filter(col("importe_neto") < 0).count() == 0),
        ("canal_valido",       df.filter(
            ~col("canal").isin(["ONLINE", "TIENDA", "B2B", "TELEFONO"])
        ).count() == 0),
    ]
    
    failed = [name for name, ok in checks if not ok]
    if failed:
        raise ValueError(f"Validaciones fallidas en Silver: {failed}")
    
    print(f"Todas las validaciones OK ({total:,} registros)")
```

### ¿Cuándo usar dos capas en vez de tres?

<div class="callout callout-info">
  <strong>Para proyectos pequeños</strong>
  Para proyectos pequeños o equipos sin ingeniería de datos, dos capas pueden ser suficientes: <strong>Raw → Analytic</strong> (Raw = Bronze directo, Analytic = Silver+Gold combinados). Menos overhead, misma lógica. La complejidad de Medallion debe justificarse por el volumen y la complejidad del dato.
</div>

## Conclusión

La arquitectura Medallion no es complejidad por el gusto de la complejidad. Es una solución pragmática a un problema real: los datos de negocio son sucios, incompletos y cambian constantemente.

<div class="callout callout-tip">
  <strong>El punto de partida</strong>
